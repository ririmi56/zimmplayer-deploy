{{ if .Values.snapcast.enabled -}}
Snapcast
--------
Snapserver est deploye et l'API pointe dessus. Deux points a connaitre :

  - les snapclients PHYSIQUES du reseau doivent joindre le port 1704 du
    service {{ include "zimmplayer.snapserverService" . }}. Il est en
    {{ .Values.snapcast.service.type }} : {{ if eq .Values.snapcast.service.type "ClusterIP" }}il n'est donc PAS joignable hors du
    cluster. Passer snapcast.service.type a LoadBalancer ou NodePort.{{ else }}verifier l'adresse obtenue avec
    `kubectl -n {{ .Release.Namespace }} get svc {{ include "zimmplayer.snapserverService" . }}`.{{ end }}

  - redemarrer snapserver seul lui fait perdre les flux enregistres par
    l'API. Redemarrer l'API ensuite les reinscrit tous :

        kubectl -n {{ .Release.Namespace }} rollout restart deploy/{{ include "zimmplayer.fullname" . }}-api

Ne pas modifier l'adresse annoncee depuis l'ecran Configuration : elle serait
ecrite en base et prendrait le pas sur celle que la chart calcule.
{{- else -}}
Snapcast
--------
Snapserver n'est pas deploye (snapcast.enabled: false). Pour brancher celui du
reseau, renseigner son adresse depuis l'ecran Configuration de
l'application ; le reglage est conserve en base.
{{- end }}
